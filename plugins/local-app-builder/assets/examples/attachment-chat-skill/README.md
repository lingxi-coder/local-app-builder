# Attachment Review Chat

A schema-2 Local App example for persistent AG-UI 1.0 threads, browser `File` attachments and a packaged runtime Skill. Copy this directory into a project and publish it with `LocalApp({"bundle_path":"/absolute/copied/project"})`. Configure an App model in trusted Apps UI before using Agent features.

The app pages through `chats.list()` and each Chat's official `Message[]` history. It creates an `AbstractAgent` client with `threadId` equal to the Chat ID and the displayed history as `initialMessages`. Startup only restores history and never calls `runAgent()`. For each new turn it keeps that history for display, sets the run client's messages to only the new official user `Message`, and runs with a fresh `runId`. The Chat's durable Harness Session supplies canonical prior context, so older text and File bytes are not sent again on every turn. This keeps a valid new turn below the 116 MiB RunAgentInput limit even after the Chat accumulates files under its larger 256 MiB asset cap. The new message uses text and standard `ContentPart`s returned by `localApp.agent.file(file)`; the helper carries the filename in versioned content-part metadata, which the app preserves.

When IndexedDB is available, the app keeps a short-lived local retry draft containing the original browser `File` objects, Chat ID, message ID and public `runId`. Ordinary refresh does not send it. If that user message is already in host history, the app gets the task by `runId`, checks its canonical `threadId`, creates a fresh client without `initialMessages`, and calls `connectAgent({runId})` to replay events read-only. It clears the draft only after a successful terminal event. `RUN_ERROR`, cancellation, interruption, a missing terminal event or a reconnect failure leave the exact input and `runId` saved; they never start another model request automatically. A user may explicitly check the unchanged draft and `runId`; it expires after 24 hours. If IndexedDB is unavailable, online use remains available but the page cannot restore its local retry draft after refresh. The host SDK separately persists the complete AG-UI input for the iOS foreground wake-and-return flow and correlates it by `runId`. The SDK accepts at most eight files, 25 MiB each and 50 MiB total; its run ledger has 32-record/100 MiB caps, 24-hour pending retention and 7-day run-ID receipts.

The review Skill is immutable instruction text; it grants no tools, and this example declares none. The host controls the model, authorization, approvals and transcript. Mobile pages use the actual OS-selected external browser without branching on browser brand. iOS has a finite foreground continuation lease; physical-device acceptance is separate from source checks and browser previews.
