# Attachment Review Chat

A schema-2 Local App example for persistent AG-UI 1.0 threads, browser `File` attachments and a packaged runtime Skill. Copy this directory into a project and publish it with `LocalApp({"bundle_path":"/absolute/copied/project"})`. Configure an App model in trusted Apps UI before using Agent features.

The app pages through `chats.list()` and each Chat's official `Message[]` history. It creates an `AbstractAgent` client with `threadId` equal to the Chat ID and the displayed history as `initialMessages`. Startup only restores history and never calls `runAgent()`. For each new turn it keeps that history for display, sets the run client's messages to only the new official user `Message`, and runs with a fresh `runId`. The Chat's durable Harness Session supplies canonical prior context, so older text and File bytes are not sent again on every turn. This keeps a valid new turn below the 116 MiB RunAgentInput limit even after the Chat accumulates files under its larger 256 MiB asset cap. The new message uses text and standard `ContentPart`s returned by `localApp.agent.file(file)`; the helper carries the filename in versioned content-part metadata, which the app preserves.

When IndexedDB is available, before sending the app saves a short-lived retry draft with the Chat ID, `runId`, and the exact generated user Message and its file parts. The helper generates a fresh part ID on each call, so retries reuse those parts instead of converting the Files again. The app prevents concurrent submissions from repeated clicks in the same page. Ordinary refresh does not send a saved draft. On an explicit Retry, it looks up the same `runId` first, checks its canonical `threadId`, and, if found, uses a fresh client without `initialMessages` to `connectAgent({runId})` and observe events read-only through a terminal outcome. It also does this when the Chat history has not yet exposed the message. An immediate `task_not_found` is a lookup miss, not a model failure; the app retries that read. If the message is already in history, it never resubmits after lookup misses. Otherwise the explicit Retry can resend the unchanged input under the same `runId`, relying on the host's matching-input admission check while its records are available. This does not make external tool effects idempotent. If the saved input is missing or incomplete, the app permits a read-only check but cannot safely resubmit it.

The draft expires after 24 hours and is removed when checked. `RUN_ERROR`, cancellation, interruption, a missing terminal event or a reconnect failure leave it available; none starts another model request automatically. If IndexedDB is unavailable, the current Mobile SDK cannot reserve and submit Agent inputs, and this example disables Send. Desktop host behavior may differ; without the app's draft storage it cannot restore the draft after refresh. On Mobile, the SDK separately persists complete pending inputs, including file data, for handoff and same-ID correlation. Its records expire after 24 hours for pending inputs and 7 days for accepted run-ID receipts; limits are 32 records/100 MiB. On `localApp:agent-handoff-error` with `pending_request_missing`, the app directs the user to the original tab or a context sharing that storage. The SDK accepts at most eight files, 25 MiB each and 50 MiB total. Browser storage can be cleared or inaccessible. Forgetting the app's draft does not cancel a run or delete host Chat history or SDK-owned handoff data.

The review Skill is immutable instruction text; it grants no tools, and this example declares none. The host controls the model, authorization, approvals and transcript. Mobile pages use the actual OS-selected external browser without branching on browser brand. On supported iOS 26+ hosts, a user-initiated task may receive finite system-managed continued processing; it can expire or be terminated, and neither completion nor immediate wake is guaranteed. After interruption return to LingXi and check the saved run. Physical-device acceptance is separate from source checks and browser previews.

Run the focused simulated recovery checks with `node --test scripts/tests/test-attachment-chat-recovery.mjs` from the builder repository.
